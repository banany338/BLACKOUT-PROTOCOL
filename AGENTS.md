# Project documentation preference

The user wants documentation with every meaningful project change or decision so they can understand what is happening.

- Update `docs/PROJECT_UPDATES.md` during each implementation turn. Use plain language: what changed, why, how the user can try it, what was checked, and what remains unfinished.
- Update `docs/USER_GUIDE.md` whenever controls or user workflows change. Keep README links current.
- Describe implemented behaviour separately from plans and assumptions. Do not imply that a simulated recovery actually changes a provider account.
- Keep explanations in the documentation and chat; the user wants little text on each application screen.
- Link the updated documentation in the final response. Documentation-only edits do not need software tests.
